# Security policy

Security issues in the framework tooling, integrity checks, release provenance, schemas, or automation should be reported privately where possible rather than disclosed first in a public issue.

For ordinary license interpretation questions or suspected third-party violations, use the corresponding issue forms; those are not software-security vulnerabilities.

Do not include private commercial agreements, private grant documents, personal identity data, signing private keys, tokens, or confidential infringement evidence in a public report.
