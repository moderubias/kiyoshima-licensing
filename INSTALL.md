# Install / upgrade

## Upgrade Framework 1.2.0-rc1 to 1.2.0-rc2 from Downloads

This overlay is designed to be extracted over an existing Framework 1.2.0-rc1
clone. It does not contain `.git` or `.venv`. Kiyoshima Source 1.0 rc.3 legal
bytes and Passport schema 1.3 are unchanged; rc2 is a tooling/layout release.

Locate the clone through the installed command:

```bash
KLICENSE_BIN="$(command -v klicense)"
KLICENSE_SCRIPT="$(readlink -f "$KLICENSE_BIN")"
KLICENSE_ROOT="$(cd "$(dirname "$KLICENSE_SCRIPT")/.." && pwd)"
printf 'klicense: %s\nframework: %s\n' "$KLICENSE_BIN" "$KLICENSE_ROOT"
cd "$KLICENSE_ROOT"
```

If the previous rc1 work is staged but not committed, unstage it without losing
working-tree changes before applying rc2:

```bash
git reset
```

If rc1 is already committed, leave it committed and apply rc2 as a new commit.
In either case, create a filesystem backup before overlaying files:

```bash
BACKUP="../kiyoshima-licensing.backup-$(date -u +%Y%m%dT%H%M%SZ)"
cp -a . "$BACKUP"
echo "Backup: $BACKUP"
```

Apply the archive downloaded to `~/Downloads`:

```bash
unzip -o ~/Downloads/kiyoshima-licensing-framework-1.2.0-rc2-overlay.zip -d .
```

Verify:

```bash
klicense --version
klicense verify-framework
python3 -m unittest discover -s tests -v
python3 -m py_compile tools/klicense.py
git diff --check
git status --short
```

Expected version:

```text
klicense 1.2.0-rc2 (Passport schema 1.3)
```

The installed `~/.local/bin/klicense` symlink normally needs no reinstall because
its target `tools/klicense.py` was updated in place. If necessary:

```bash
bash tools/install-cli.sh
```

## Compact projects created by Framework 1.2.0-rc1

Preview first:

```bash
klicense compact-project /path/to/project
```

Apply after reviewing the plan:

```bash
klicense compact-project /path/to/project --apply
klicense verify-project /path/to/project
klicense doctor /path/to/project
```

`compact-project` creates an external timestamped backup. It removes only
recognized generated/redundant files. Customized NOTICE/REUSE/snippet files are
preserved.

For a dual `MIT OR Apache-2.0` Open project, the lean result is:

```text
KIYOSHIMA.json
LICENSE
LICENSES/
  Apache-2.0.txt
  MIT.txt
```

`LICENSE` becomes a short dual-license notice. The complete standard texts remain
under `LICENSES/`. `LICENSE-MIT`, `LICENSE-APACHE`, generated `NOTICE`, and
generated `REUSE.toml` are removed when they match the old generated bytes.

## Fresh project defaults

New projects are lean by default. Extra compliance/documentation files are
explicit opt-ins:

```bash
--notice
--reuse
--readme-snippet docs/README-LICENSING.md
```

For example:

```bash
klicense init-project /path/to/project \
  --profile open \
  --open-license "MIT OR Apache-2.0" \
  --name YourProject \
  --kind library \
  --repository https://github.com/owner/project \
  --holder "Copyright Holder"
```

## Existing Kiyoshima Source projects

`sync-project` remains the Source-project synchronization command:

```bash
klicense sync-project /path/to/project --dry-run
klicense sync-project /path/to/project
```

Framework 1.2.0-rc2 no longer creates a duplicate Source `LICENSES/` copy merely
because sync ran. If a project already uses that REUSE copy, sync preserves and
updates it.

## Release state

Kiyoshima Source 1.0 remains a legal release candidate. `klicense release-check`
is expected to fail until software/IP legal review and the explicit final freeze
are completed.
