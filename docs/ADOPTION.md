# Adoption

## For your own project

1. Choose a profile: Open, Source, or Commercial.
2. For Source, copy the exact Kiyoshima Source License 1.0 text into `LICENSE` and `LICENSES/LicenseRef-Kiyoshima-Source-1.0.txt`.
3. Copy `templates/project/KIYOSHIMA.json` to the repository root and fill project identity fields.
4. Add the README licensing notice from `templates/project/README-LICENSING.md`.
5. Add `SPDX-License-Identifier: LicenseRef-Kiyoshima-Source-1.0` to commentable source files where practical, or use `REUSE.toml` for bulk mappings.
6. Preserve the license text exactly. Put project-specific facts in `NOTICE` and `KIYOSHIMA.json`, not inside the legal text.
7. Optionally register the project in the canonical adopter registry.

## Why another developer might adopt it

Kiyoshima Source is intentionally opinionated: it gives natural persons broad freedom while preserving a direct permission boundary for organizational monetization. The value proposition is not "yet another custom license"; it is a complete operational layer:

- clear human policy;
- stable canonical version;
- machine-readable permission passport;
- AI-agent semantics;
- explicit AI-training reservation;
- standard commercial and special-grant paths;
- integrity hashes and release provenance;
- optional public adopter registry.

A third-party project can use the license without transferring ownership or joining any organization. Exact license copies are reusable under Section 21.

## Registry model

Adoption registration is optional. A registered project should provide its repository URL, declared profile, license identifier, License Passport hash, and contact route. Registration is evidence of a public declaration, not certification of legal compliance.
