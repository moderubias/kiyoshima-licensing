# Source-available model comparison

This is a positioning document, not a legal-equivalence claim. Compare the
actual license texts before adopting any model.

| Model | Core public-use boundary | Automatic future OSS transition | Distinctive axis |
|---|---|---|---|
| Kiyoshima Source 1.0 candidate | Broad natural-person use + qualifying education/research; organization production/commercial/hosted/model-improvement use separately licensed | No | Human/organization split, explicit AI reservation, License Passport protocol |
| Business Source License 1.1 | Non-production use by default; licensor may add an Additional Use Grant | Yes, by Change Date and no later than the fourth anniversary, to a qualifying Change License | Time-delayed Open Source conversion |
| Functional Source License 1.1 | Broad use except defined Competing Use | Yes, after two years to Apache-2.0 or MIT variant | Anti-competitive-use boundary + fixed conversion |
| PolyForm family | Depends on selected standardized variant: noncommercial, trial, internal, small-business, shield/perimeter, etc. | Variant-dependent; Countdown handles scheduled changes | Menu of standardized source-available policies |

Primary references:

- OSI Open Source Definition: https://opensource.org/osd
- MariaDB BSL 1.1: https://mariadb.com/bsl11/
- FSL: https://fsl.software/
- PolyForm licenses: https://polyformproject.org/licenses

Kiyoshima should not compete by adding arbitrary restrictions. The intended
technical differentiator is a conservative, machine-readable operational layer
around whichever controlling legal instrument a project actually uses.
